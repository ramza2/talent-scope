# 02. MVP Scope

## 1. 1차 MVP 정의

1차 MVP의 목표는 **인력 문서를 등록·분석하여 구조화된 인력 프로필을 만들고, 사용자가 관련 인력을 검색할 수 있는 상태까지 구현하는 것**이다.

```text
이력서/프로필 확보
  → 시스템 업로드
  → 원본 파일 저장
  → Parser/VLM 분석
  → LLM 구조화
  → 기존 DB 비교
  → 사용자 검토·확정
  → Profile DB 반영
  → Embedding 생성
  → 인력 검색/조회
```

## 2. MVP 포함 범위

### 문서 관리
- 문서 업로드
- 다중 파일 업로드
- 문서종류 지정
- 원본 파일 보관
- 미리보기 및 다운로드
- 버전관리
- 중복파일 확인
- 분석/임베딩 처리상태 관리

### AI 문서분석
- Text Parser 기반 직접 추출
- 필요한 경우 VLM 보조
- LLM 기반 Profile JSON 구조화
- JOB / TECH / EXP / BIZ / CUSTOMER_TYPE 정규화
- 프로젝트 단위 경력 추출
- 원문 근거 및 Confidence 관리
- 기존 DB와 NEW / SAME / UPDATE / CONFLICT 비교
- 사용자 승인·수정·거절

### 인력 프로필
- 기본정보
- 직무
- 기술
- 전문분야
- 사업분야/고객유형
- 프로젝트 경력
- 근무경력
- 학력
- 자격증
- 프로필 요약
- 원본문서 연결
- 변경이력

### 검색
- 조건검색
- 계층/동의어 검색
- 자연어 검색조건 생성
- Required / Preferred 조건 구분
- Keyword / Full Text Search
- Profile / Project / Document Vector Search
- Hybrid Search
- Person 기준 결과 병합
- Hard Filter
- Backend Ranking
- 추천근거 및 원본문서 Drill-down

### 사용자/권한
- ID/Password 로그인
- 일반사용자 / 관리자 2개 역할
- 일반사용자는 사내 인력정보 및 일반 문서를 마스킹 없이 조회 가능
- 관리자는 등록·수정·분석확정·삭제·코드/사용자 관리 수행
- 주민등록번호, 계좌번호, 신분증번호 등 불필요한 민감정보는 구조화/임베딩 대상에서 제외

## 3. 1차 MVP 제외 범위

다음은 1차 MVP 이후 고도화 범위로 둔다.

### 투입·후보인력 관리
- 사업별 인력요청
- 후보 발굴 Pipeline
- Shortlist
- 고객 제안
- 최종 확정
- 투입예정/실제투입
- 일정충돌 및 투입이력

### 소싱업체·외부인력 Workflow
- 소싱업체 Master 및 담당자
- 업체별 추천요청
- 추천 회신 및 단가 협의
- 외부인력 계약
- 월별 정산 및 집행현황

### 권한 고도화
- 개인정보 마스킹 설정
- 필드별 ACL
- 부서별/프로젝트별 접근권한
- 문서별 권한
- 다운로드 승인
- SSO/LDAP/AD 연계
- 2FA

### 기타 운영 고도화
- 알림/리마인더
- 대규모 통계·리포팅
- 업체/후보 성과분석
- 근태/정산 연계

## 4. MVP 완료 판단 기준

다음 사용자 시나리오가 End-to-End로 동작하면 1차 MVP의 핵심 목표를 달성한 것으로 본다.

1. 관리자가 신규 인력의 이력서/프로필을 업로드한다.
2. 시스템이 문서를 분석하여 구조화된 Candidate Profile을 생성한다.
3. 관리자가 AI 추출 결과와 원문 근거를 확인하고 확정한다.
4. 확정된 프로필이 인력 목록/상세에 표시된다.
5. 일반사용자가 조건검색 또는 자연어로 인력을 검색한다.
6. 관련 인력이 적합도와 근거와 함께 조회된다.
7. 사용자가 관련 프로젝트와 원본 이력서/경력기술서를 확인할 수 있다.
