# 11. Core Screen Wireframes

## 1. 문서 목적

본 문서는 TalentScope 1차 MVP의 핵심 사용자 흐름인 `문서 등록 → AI 분석 검토 → 인력 상세 조회 → 통합 인력검색`에 해당하는 4개 핵심 화면을 Wireframe 수준으로 정의한다.

핵심 화면:

1. 신규 인력 등록 및 문서 업로드
2. AI 분석 결과 검토·확정
3. 인력 상세 프로필
4. 통합 인력검색 및 검색결과

`인력 목록`은 핵심 업무 흐름을 보조하는 관리 화면으로 본 문서 Appendix에 함께 정리한다. 전체 메뉴와 화면 관계는 [10. Information Architecture](10_ia.md)를 기준으로 한다.

## 2. 공통 UI 원칙

- Desktop 우선으로 설계한다.
- 좌측 Navigation + 상단 Header + Main Content 구조를 공통으로 사용한다.
- 일반사용자와 관리자의 조회 화면은 최대한 동일하게 유지한다.
- 등록·수정·AI 확정·삭제 등 관리 기능 버튼은 관리자에게만 노출한다.
- 연락처, 이메일 등 일반 인력정보는 사내 사용자에게 마스킹 없이 표시한다.
- AI 결과는 사용자가 확정하기 전까지 Confirmed Profile을 직접 변경하지 않는다.
- 기술·직무·프로젝트 등 주요 데이터에서 원본문서 Evidence로 Drill-down 할 수 있게 한다.
- Frontend는 LLM/VLM Runtime을 직접 호출하지 않고 Backend API를 사용한다.

# 3. 신규 인력 등록 및 문서 업로드

## 3.1 화면 목적

사람 정보를 먼저 수기로 입력하는 방식이 아니라 이력서·프로필·경력기술서를 먼저 업로드하고, AI가 최소 식별정보와 상세 프로필을 추출하도록 한다.

전체 흐름:

```text
① 문서 업로드
  → ② 기본정보/기존 인력 확인
  → ③ 신규 또는 기존 인력 연결
  → AI 상세분석 시작
  → AI 분석 결과 검토
```

## 3.2 Step 1 - 문서 업로드

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 신규 인력 등록                                                            │
│ 이력서·프로필 문서를 등록하면 AI가 인력정보를 분석합니다.                  │
│                                                                            │
│ ① 문서 업로드  ───── ② 인력 확인 ───── ③ 분석 시작                       │
│      ●                  ○                  ○                               │
│                                                                            │
│ ┌────────────────────────────────────────────────────────────────────────┐ │
│ │                                                                        │ │
│ │        이력서·프로필 파일을 Drag & Drop                               │ │
│ │                                                                        │ │
│ │                         [파일 선택]                                    │ │
│ │                                                                        │ │
│ │ HWP/HWPX · DOC/DOCX · PDF · PPT/PPTX · JPG/PNG                       │ │
│ └────────────────────────────────────────────────────────────────────────┘ │
│                                                                            │
│ 업로드 파일                                                               │
│                                                                            │
│ 홍길동_이력서.hwp             1.8MB                                      │
│ 문서종류 [이력서 ▼]                              [삭제]                    │
│ ───────────────────────────────────────────────────────────────────────── │
│ 홍길동_경력기술서.pptx        3.4MB                                      │
│ 문서종류 [경력기술서 ▼]                          [삭제]                    │
│ ───────────────────────────────────────────────────────────────────────── │
│ 정보처리기사.jpg               850KB                                     │
│ 문서종류 [자격증 ▼]                              [삭제]                    │
│                                                                            │
│                                              [취소] [다음: 인력 확인 →]   │
└────────────────────────────────────────────────────────────────────────────┘
```

### 영역 및 동작

| 영역/버튼 | 동작 |
|---|---|
| Drag & Drop | 여러 파일을 동시에 업로드 Queue에 추가한다. |
| 파일 선택 | OS File Dialog를 열고 다중 선택을 지원한다. |
| 문서종류 | 파일명/내용을 바탕으로 자동 제안하되 사용자가 수정할 수 있다. |
| 삭제 | 최종 등록 전 Upload Queue에서 파일을 제거한다. |
| 다음: 인력 확인 | 최소 1개 이상의 유효 문서가 있을 때 활성화한다. 임시 저장 후 최소 식별정보 추출을 시작한다. |
| 취소 | 등록 Flow를 종료한다. 임시 파일은 즉시 또는 TTL 정책으로 삭제한다. |

지원 문서종류는 이력서, 인력 프로필, 경력기술서, KOSA/경력증명, 자격증, 포트폴리오, 기타로 한다.

업로드 직후 Backend에서 확장자, MIME Type, 파일 크기, 손상/암호화 여부, Hash를 검사한다. 동일 Hash가 이미 존재하면 기존 문서를 안내하고 사용자가 계속 등록할지 결정한다.

```text
│                                                                            │

│                                                                            │

│                                                                            │
│ 이름       [홍길동                         ]                               │
│ 소속       [ABC테크                        ]                               │
│ 연락처     [010-1234-5678                 ]                               │
│ 이메일     [hong@example.com              ]                               │
│                                                                            │
│ 중복 인력 확인                                                            │
│ ───────────────────────────────────────────────────────────────────────── │
```

최소 식별정보는 이름, 소속, 연락처, 이메일을 사용한다. AI가 잘못 읽은 값은 이 단계에서 직접 수정할 수 있다.

중복 후보 판단은 이메일 일치, 전화번호 일치, 이름+소속 일치 등을 우선 사용하며 AI가 자동 병합하지 않는다.

중복 후보가 발견되면 다음과 같이 표시한다.

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ ⚠ 기존 인력과 동일할 가능성이 있습니다.                                  │
│                                                                            │
│ 홍길동                                                                     │
│ ABC테크 · 특급 · AI개발자                                                 │
│ hong@example.com · 010-1234-5678                                          │
│ 최근 갱신 2026-05-18                                                      │
│                                                                            │
│ [기존 프로필 보기]                                                        │
│                                                                            │
│ 처리 방법                                                                 │
│ ● 기존 인력에 새 문서를 추가                                             │
│ ○ 신규 인력으로 등록                                                     │
│                                                                            │
│                                             [← 이전] [계속 →]             │
└────────────────────────────────────────────────────────────────────────────┘
```

동명이인 가능성이 있으므로 사용자가 신규 인력 등록을 선택할 수 있어야 한다.

## 3.4 Step 3 - 분석 시작

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 신규 인력 등록                                                            │
│                                                                            │
│ ① 문서 업로드  ───── ② 인력 확인 ───── ③ 분석 시작                       │
│      ✓                  ✓                  ●                               │
│                                                                            │
│ 홍길동                                                                     │
│                                                                            │
│ 등록 문서                                                                 │
│ ✓ 이력서             홍길동_이력서.hwp                                   │
│ ✓ 경력기술서         홍길동_경력기술서.pptx                              │
│ ✓ 자격증             정보처리기사.jpg                                    │
│                                                                            │
│ AI 분석 예정 항목                                                         │
│ 기본정보 · 직무 · 기술 · 전문분야 · 프로젝트 · 학력 · 자격증             │
│ 사업분야 · 고객유형                                                       │
│                                                                            │
│ 분석 결과는 자동 반영되지 않으며 검토 후 최종 확정합니다.                │
│                                                                            │
│                                               [AI 분석 시작]              │
└────────────────────────────────────────────────────────────────────────────┘
```

`AI 분석 시작`은 비동기 Job을 생성한다.

```text
Document Processing Job
  → Parser
  → 필요한 경우 VLM
  → Qwen3-14B Profile 구조화
  → 기존 Confirmed Profile 비교
  → Candidate Profile 생성
```

사용자는 분석 중 다른 화면으로 이동할 수 있으며 완료 후 `AI 분석 검토` Queue에서 결과를 확인한다. 일부 문서만 실패한 경우 성공한 문서의 결과는 유지하고 실패 문서에 대해 재분석을 지원한다.

# 4. AI 분석 결과 검토·확정

## 4.1 화면 목적

AI Candidate Profile과 기존 Confirmed Profile의 차이만 빠르게 검토하고, 원문 근거를 확인한 뒤 사용자가 승인한 정보만 운영 Profile DB에 반영한다.

기본적으로 SAME 항목은 숨기고 NEW / UPDATE / CONFLICT / REVIEW 중심으로 표시한다.

## 4.2 Wireframe

```text
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ AI 분석 결과 검토                                                                        │
│ 홍길동 · 경력기술서 v3 · 2026-09-04                                                     │
│                                                                                          │
│ 신규 7 | 변경 3 | 충돌 1 | 확인필요 2 | 동일 24         검토 9 / 13                    │
│                                                                                          │
│ ☑ 변경항목만    □ 확인필요만                                   [원문 보기 ☑]             │
│                                                                                          │
│ [기본정보] [직무·기술] [전문분야] [프로젝트] [학력·자격]                               │
│                                                                                          │
│ ┌────────────────────────────────────────────────┬─────────────────────────────────────┐ │
│ │ 총 경력                                변경     │ 원본문서                            │ │
│ │                                                │                                     │ │
│ │ 기존                신규                       │ 경력기술서 v3                       │ │
│ │ 16년 2개월          17년 10개월               │                                     │ │
│ │                     신뢰도 높음                │ ┌─────────────────────────────────┐ │ │
│ │                                                │ │           PDF VIEWER            │ │ │
│ │ ○ 기존 유지                                  │ │             p.1                 │ │ │
│ │ ● 신규 적용                                  │ └─────────────────────────────────┘ │ │
│ │ ○ 직접 수정                                  │                                     │ │
│ │ 근거: p.1                     [근거 보기]      │ "총 경력 17년 10개월"              │ │
│ ├────────────────────────────────────────────────┤                                     │ │
│ │ AI개발자                               신규    │                                     │ │
│ │ AI Engineer → AI개발자                        │                                     │ │
│ │ [✓ 추가] [제외] [분류 변경] [근거 보기]      │                                     │ │
│ ├────────────────────────────────────────────────┤                                     │ │
│ │ RAG                                  확인필요  │                                     │ │
│ │ AI 추론 · 신뢰도 확인 권장                    │                                     │ │
│ │ [✓ 추가] [제외] [근거 보기]                  │                                     │ │
│ └────────────────────────────────────────────────┴─────────────────────────────────────┘ │
│                                                                                          │
│ [신뢰도 높은 신규항목 일괄 적용]                                                        │
│                                                                                          │
│ [임시저장]       [나중에 검토]                          [확정 및 Profile 반영]           │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

## 4.3 상태 정의 및 검토 방식

| 상태 | 의미 | 기본 처리 |
|---|---|---|
| SAME | 기존값과 동일 | 기본 숨김 |
| NEW | 기존 DB에 없던 신규 정보 | 추가/제외/수정 |
| UPDATE | 최신 문서에 의해 변경 가능성이 있는 값 | 기존 유지/신규 적용/수정 |
| CONFLICT | 기존값과 명확하게 상충 | 사용자가 반드시 선택 |
| REVIEW | 낮은 Confidence 또는 AI 추론 정보 | 사용자 확인 권장/필수 |

단일 필드는 `기존값 ↔ 신규값` 비교 방식을 사용하고, 직무·기술·전문분야처럼 복수값인 데이터는 Tag/Checkbox 방식으로 승인한다.

## 4.4 원본문서 Viewer

화면 오른쪽 30~35%를 Evidence Viewer로 사용한다. `[근거 보기]`를 누르면 해당 문서와 페이지로 이동하고 가능하면 근거 문장을 Highlight한다.

```text
항목: RAG
근거: 경력기술서 v3 / p.8
"Vector DB 기반 문서검색과 LLM 응답 생성 구현"
[원문에서 보기]
```

문서에 직접 기재된 정보와 AI가 문맥으로 추론한 정보는 `문서 직접 확인 / AI 추론`으로 구분한다.

## 4.5 프로젝트 검토

프로젝트는 Card 단위로 검토한다.

```text
┌───────────────────────────────────────────────────────────────┐
│ 신규 프로젝트                                      신규      │
│                                                               │
│ ○○기관 AI 지식검색 플랫폼 구축                              │
│ 기간       2025.01 ~ 2025.12                                 │
│ 고객       ○○공사                                           │
│ 역할       PL / AI개발자                                     │
│ 기술       Python / FastAPI / Qwen / RAG / pgvector         │
│ 담당업무   RAG 아키텍처 설계 및 Backend 개발                 │
│                                                               │
│ [✓ 프로젝트 추가] [제외] [수정] [원문 근거]                 │
└───────────────────────────────────────────────────────────────┘
```

기존 프로젝트와 유사하면 `기존 프로젝트에 병합 / 별도 프로젝트로 추가 / 제외`를 선택한다. 병합 전에는 기간, 역할, 기술, 담당업무 등이 어떻게 합쳐지는지 미리 보여준다.

## 4.6 주요 버튼

| 버튼 | 동작 |
|---|---|
| 변경항목만 | SAME 항목을 숨기고 검토대상만 표시한다. 기본 ON. |
| 원문 보기 | 우측 Evidence Viewer를 열고 닫는다. |
| 근거 보기 | 선택한 항목의 문서/페이지/근거문장으로 Viewer를 이동한다. |
| 분류 변경 | AI가 정규화한 JOB/TECH/EXP 코드를 다른 표준코드로 수정한다. |
| 신뢰도 높은 신규항목 일괄 적용 | NEW + High Confidence + Explicit 항목만 일괄 승인한다. CONFLICT는 제외한다. |
| 임시저장 | 현재 Review Decision을 저장하고 상태를 REVIEWING으로 유지한다. |
| 나중에 검토 | 검토 목록으로 이동한다. 저장되지 않은 변경이 있으면 경고한다. |
| 확정 및 Profile 반영 | 미처리 CONFLICT/필수 REVIEW가 없는지 확인 후 최종 Summary Modal을 표시한다. |

확정 후 Backend는 Review Decision 저장 → Confirmed Profile/Project 갱신 → 변경이력 기록 → 검색 Summary/Embedding 재생성 → Search Index 갱신 순으로 처리한다.

# 5. 인력 상세 프로필

## 5.1 화면 목적

한 사람의 확정된 인력정보를 한 화면에서 이해하고, 직무·기술·프로젝트·학력·자격·원본문서·변경이력까지 Drill-down 한다.

첫 화면은 모든 원시 데이터를 나열하기보다 해당 인력을 빠르게 판단할 수 있는 Summary 중심으로 구성한다.

## 5.2 기본 Wireframe

```text
┌──────────────────────────────────────────────────────────────────────────────────────┐
│ ← 인력 목록                                                                          │
```

### 프로젝트 경력

프로젝트는 최신순으로 정렬하고 역할, 사업분야, 기술, 기간 Filter를 제공한다. 기본은 Compact Row이며 사용자가 펼치면 고객, 고객유형, 역할, 기술, EXP, 담당업무, 원문 Evidence를 확인한다.

### 문서

```text

v3 홍길동_이력서_202603.docx
   [미리보기] [다운로드]
```

미리보기는 PDF/이미지는 직접, HWP/DOCX/PPTX는 서버에서 생성한 Preview PDF를 사용한다. 다운로드 시 사용자·인력·문서·일시를 기록한다.

### 변경이력

문서 등록, AI 분석 확정, 사용자 직접수정 등을 Timeline으로 보여준다. 상세보기에서는 변경 전/후 값을 확인할 수 있다.

## 6.3 자연어 검색

사용 예:

```text
Oracle DBA 15년 이상 특급 인력 찾아줘
병원 프로젝트 경험 있는 PM
AI Agent 개발 경험 있는 백엔드 개발자
Java 개발 경험 있으면서 공공사업 많이 한 PL
```

`AI 조건 해석`을 누르면 바로 검색하지 않고 Search Query를 먼저 생성하여 사용자에게 보여준다.

예:

```text
필수
[AI개발자] [특급]

선호
[RAG]

의미검색
"LLM/RAG 기반 AI 시스템 개발 경험"
```

`반드시`, `최소`, `~경험 있어야` 등은 문맥에 따라 required로, `우대`, `가능하면`, `있으면 좋음` 등은 preferred로 해석한다. 모호한 질의는 과도한 필수조건을 생성하지 않고 넓은 AI/EXP Semantic Query로 검색한다.

## 6.4 상세 Filter

| Filter | 데이터 기준 | 동작 |
|---|---|---|
| 직무 | JOB | 계층형 Multi Select. 상위 선택 시 하위 포함 가능 |
| 등급 | 기술등급 | 초/중/고/특급 및 `고급 이상` 등 범위 지원 |
| 경력 | 총 경력 | 최소/최대 년수 또는 Preset |
| 기술 | TECH | 검색형 Multi Select. 기본 OR, 필요 시 모두 포함 |
| 전문분야 | EXP | 생성형AI, RAG, AI Agent, DB튜닝 등 |
| 사업분야 | BIZ | 공공, 국방, 의료, 금융, 제조 등 |
| 고객유형 | CUSTOMER_TYPE | 공공기관, 군, 병원, 금융기관 등 |
| 소속 | affiliation | 현재 소속회사 기준 |
| 자격증 | Certification | 표준 자격명 기준 |
| 프로젝트 키워드 | Project | 프로젝트명, 고객명, 담당업무, 설명 Full-text 검색 |
| 의미검색 | Vector | Profile/Project/Document Embedding 검색문장 |

검색조건 기본 논리:

```text
서로 다른 필드 간 = AND
동일 필드 내 복수값 = OR
```

예:

```text
직무 = DBA
AND
기술 = Oracle OR Tibero
AND
사업분야 = 금융 OR 공공
```

수동 Filter는 기본적으로 Required 조건으로 처리한다.

## 6.5 검색 실행

`인력 검색` 클릭 시 Backend가 다음을 수행한다.

```text
Structured DB Search
+ Keyword / Full Text Search
+ Vector Search
→ Person ID 기준 Candidate Merge
→ Required Hard Filter
→ Backend Ranking
→ Evidence 구성
→ 결과 반환
```

필수조건은 Semantic Score보다 우선한다. LLM은 후보 전체를 직접 점수화하지 않고 자연어 조건 해석과 결과 설명에 사용한다.

## 6.6 검색결과 Card

결과 Card에는 다음을 표시한다.

- 적합도 점수 (`94점`, `%` 표현은 사용하지 않음)
- 이름
- 기술등급 / 주 직무 / 총 경력
- 주요기술
- Required/Preferred 조건 충족상태
- 가장 관련성이 높은 프로젝트 1~2건
- 상세 프로필
- 검색근거 보기
- 원본문서

적합도는 Backend Ranking Rule로 계산하고, AI 설명은 확정 DB와 Evidence만 근거로 작성한다.

## 6.8 검색 결과 0건

필수조건을 시스템이 자동 완화하지 않는다. Backend가 실제 Count Query로 완화 가능성을 계산하고 사용자에게 제안한다.

```text

현재 필수조건
특급 · AI개발자 · RAG · 의료

조건을 완화하면
의료 조건 제외       → 3명
등급을 고급 이상     → 7명

[의료 제외하고 검색]
[고급 이상으로 검색]
```

사용자가 선택했을 때만 조건을 변경한다.
