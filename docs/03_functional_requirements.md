# 03. Functional Requirements

## 1. 기능 요구사항 개요

1차 MVP 기능을 문서관리, AI 분석, 프로필관리, 검색, 보안/관리 영역으로 구분한다.

## 2. 문서관리

| ID | 기능 | 정의 |
|---|---|---|
| DOC-01 | 문서 업로드 | 이력서·프로필·경력기술서 등 인력 관련 문서를 업로드한다. |
| DOC-02 | 다중 업로드 | 한 인력에 여러 문서를 동시에 등록한다. |
| DOC-03 | 문서종류 관리 | 이력서/프로필/경력기술서/경력증명/자격증/포트폴리오/기타로 구분한다. |
| DOC-04 | 원본 저장 | 원본 파일을 수정하지 않고 File Storage에 보관한다. |
| DOC-05 | 미리보기 | PDF/이미지는 직접, Office/HWP는 Preview PDF 변환 방식으로 미리본다. |
| DOC-06 | 다운로드 | 인력 상세 및 검색근거에서 원본 문서를 다운로드한다. |
| DOC-07 | 버전관리 | 동일 유형 문서의 과거 버전을 보존하고 최신 버전을 표시한다. |
| DOC-08 | 중복검사 | 파일 Hash를 이용해 동일 파일을 확인한다. |
| DOC-09 | 처리상태 | 업로드/분석/임베딩/실패 상태를 관리한다. |
| DOC-10 | Soft Delete | 삭제 시 즉시 물리삭제하지 않고 논리삭제한다. |

## 3. AI 문서분석

| ID | 기능 | 정의 |
|---|---|---|
| AI-01 | 문서 내용 추출 | Parser 및 VLM으로 텍스트·표·이미지를 추출한다. |
| AI-02 | Profile 구조화 | 추출 내용을 Profile JSON Schema로 구조화한다. |
| AI-03 | 코드 정규화 | JOB/TECH/EXP/BIZ/CUSTOMER_TYPE을 표준코드로 정규화한다. |
| AI-04 | 프로젝트 구조화 | 프로젝트명, 기간, 고객, 역할, 기술, 담당업무 등을 추출한다. |
| AI-05 | 근거 관리 | 추출값에 문서, 페이지/위치, 근거 Text, Confidence를 연결한다. |
| AI-06 | 기존 Profile 비교 | Candidate와 Confirmed Profile을 비교한다. |
| AI-07 | 차이 상태 생성 | SAME/NEW/UPDATE/CONFLICT 상태를 생성한다. |
| AI-08 | 프로젝트 중복판단 | 기존 프로젝트와 신규 프로젝트의 동일/유사 가능성을 판단한다. |
| AI-09 | 사용자 확정 | 관리자가 승인·거절·수정 후 DB 반영한다. |
| AI-10 | 재분석 | 모델/Prompt 개선 시 기존 문서를 재분석한다. |
| AI-11 | 분석이력 | 모델, Prompt Version, Schema Version, 분석·확정 이력을 저장한다. |
| AI-12 | 임베딩 생성 | 확정된 Profile/Project 및 원본문서 Chunk 임베딩을 생성한다. |

## 4. 인력 프로필

| ID | 기능 | 정의 |
|---|---|---|
| PRF-01 | 기본정보 | 성명, 소속, 연락처, 이메일, 거주지역 등을 관리한다. |
| PRF-02 | 경력정보 | 최초 경력일, 총 경력, 기술등급 등을 관리한다. |
| PRF-03 | 직무 | JOB 코드 기반 주/부/경험 직무를 복수 관리한다. |
| PRF-04 | 기술 | TECH 코드 기반 기술, 최근사용, 프로젝트 근거 등을 관리한다. |
| PRF-05 | 전문분야 | EXP 코드 기반 전문분야와 근거를 관리한다. |
| PRF-06 | 사업경험 | BIZ/CUSTOMER_TYPE 경험을 프로젝트 기반으로 집계한다. |
| PRF-07 | 프로젝트 경력 | 프로젝트별 기간·고객·역할·기술·담당업무를 관리한다. |
| PRF-08 | 근무경력 | 회사별 재직기간, 직위, 담당업무를 관리한다. |
| PRF-09 | 학력 | 학교, 전공, 학위, 기간을 관리한다. |
| PRF-10 | 자격 | 자격명, 발급기관, 취득일, 증빙문서를 관리한다. |
| PRF-11 | 요약 | AI 생성 요약과 사용자 확정 요약을 관리한다. |
| PRF-12 | 원문근거 | 프로필 값에서 실제 원본문서/페이지로 이동할 수 있게 한다. |
| PRF-13 | 직접수정 | 관리자가 확정 프로필을 직접 수정한다. |
| PRF-14 | 변경이력 | AI 반영 및 사용자 수정 이력을 기록한다. |
| PRF-15 | 프로필 상태 | Active/Inactive/Archived/Deleted 상태를 관리한다. |
| PRF-16 | 최신성 | 최종 갱신일과 최신성 상태를 관리한다. |

## 5. 검색·추천

| ID | 기능 | 정의 |
|---|---|---|
| SRCH-01 | 조건검색 | 직무, 기술, 등급, 경력, 전문분야 등 구조화 조건으로 검색한다. |
| SRCH-02 | 복합검색 | 동일 항목 복수값 및 여러 항목 조합을 지원한다. |
| SRCH-03 | 계층확장 | 상위 코드 검색 시 하위 코드를 포함한다. |
| SRCH-04 | Alias | 동의어를 표준코드로 매핑한다. |
| SRCH-05 | 자연어 분석 | LLM으로 자연어를 Search Query JSON으로 변환한다. |
| SRCH-06 | 필수/선호 구분 | Required와 Preferred 조건을 구분한다. |
| SRCH-07 | 조건확인 | AI가 해석한 조건을 사용자에게 표시하고 수정할 수 있게 한다. |
| SRCH-08 | Keyword 검색 | 프로젝트 및 문서 문자열을 검색한다. |
| SRCH-09 | Vector 검색 | Profile/Project/Document 의미검색을 수행한다. |
| SRCH-10 | Hybrid Search | DB, Keyword, Vector 결과를 병합한다. |
| SRCH-11 | Hard Filter | 필수조건 미충족 후보를 제외한다. |
| SRCH-12 | Ranking | Backend 규칙으로 적합도 점수를 계산한다. |
| SRCH-13 | 추천근거 | 조건 충족, 관련 프로젝트, 원문 근거를 제공한다. |
| SRCH-14 | 원문 연결 | 검색근거에서 관련 문서와 위치로 이동한다. |
| SRCH-15 | 결과 정렬/필터 | 적합도, 경력, 갱신일 등의 정렬과 재필터를 지원한다. |
| SRCH-16 | 조건완화 제안 | 0건일 때 완화 가능한 조건을 제안하되 자동 완화하지 않는다. |

## 6. 사용자·관리

| ID | 기능 | 정의 |
|---|---|---|
| SEC-01 | 로그인 | 사용자 인증 및 세션/Token을 관리한다. |
| SEC-02 | 사용자 관리 | 사용자 생성·수정·활성/비활성을 관리한다. |
| SEC-03 | 역할 | 일반사용자/관리자 역할을 구분한다. |
| SEC-04 | API 권한 | Backend API에서 역할별 권한을 검사한다. |
| SEC-05 | 일반정보 조회 | 사내 일반사용자는 프로필 개인정보와 일반 문서를 마스킹 없이 조회한다. |
| SEC-06 | 민감정보 제외 | 주민번호·계좌번호·신분증번호 등은 구조화/임베딩 대상에서 제외한다. |
| SEC-07 | 변경이력 | 주요 등록·수정·삭제·확정 작업을 기록한다. |
| SEC-08 | 다운로드 이력 | 원본 문서 다운로드 사용자와 일시를 기록한다. |
| SEC-09 | Runtime 보호 | LLM/VLM은 Backend에서만 호출한다. |

## 7. 고도화로 이관한 기능

- 인력요청/후보/제안/확정/투입
- 소싱업체 추천 및 외부인력 Workflow
- 계약 및 정산
- 개인정보 마스킹 및 세부 ACL
