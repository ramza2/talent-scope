# 07. Profile Management

## 1. 목적

AI가 추출·확정한 인력 정보를 사람이 실제 업무에서 조회·수정·보완할 수 있는 중심 프로필 화면을 제공한다. 프로필은 기본정보, 직무/기술, 전문분야, 프로젝트 경력, 학력/자격, 원본문서, 변경이력을 한 사람 기준으로 통합 관리한다.

## 2. 상세 프로필 기본 구조

상단 Summary:
- 이름
- 주 직무
- 기술등급
- 총 경력
- 소속
- 연락처/이메일
- 주요기술
- 전문분야
- 최근 갱신일

하위 탭:
- 프로필
- 직무·기술
- 프로젝트 경력
- 학력·자격
- 문서
- 변경이력

## 3. 기본정보

관리 항목:
- 성명
- 영문명(선택)
- 프로필 사진(선택)
- 생년연도(필요 시)
- 연락처
- 이메일
- 거주지역
- 소속회사
- 부서
- 직위/직급
- 고용형태
- 기술등급
- 최초 경력 시작일
- 총 경력
- 최종 프로필 갱신일

주민등록번호 전체, 상세주소, 계좌번호 등 검색·관리 목적에 불필요한 민감정보는 구조화하지 않는다.

## 4. 총 경력 관리

경력은 계산값과 확정값을 구분할 수 있도록 한다.

- `career_start_date`
- `career_calculated_months`
- `career_document_value`
- `career_confirmed_months`

근무경력/프로젝트 기간으로 계산한 값은 보조값이며, 최종 확정값은 사용자가 검토할 수 있다.

## 5. 직무 관리

한 인력에 복수 직무를 등록한다.

- `PRIMARY`: 주 직무
- `SECONDARY`: 부 직무
- `EXPERIENCE`: 과거 경험

직무는 `JOB` 코드와 연결하고 필요 시 관련 프로젝트를 근거로 표시한다.

예:

```text
주 직무      AI개발자
부 직무      Backend Developer, PL
경험 직무    Java Developer
```

## 6. 기술 관리

기술은 단순 문자열 태그보다 다음 정보를 함께 관리한다.

- TECH 코드/표준명
- 최근 사용년도
- 경험기간(문서 명시/계산/확정 구분)
- 근거 프로젝트 수
- 관련 프로젝트
- 정보출처

AI가 숙련도를 임의로 상/중/하로 확정하지 않는다.

장기 확장용으로 `ACTIVE / RECENT / HISTORICAL` 등의 기술 상태를 둘 수 있으나 MVP에서는 최근 사용년도 중심으로 관리한다.

## 7. 전문분야

`EXP` 코드 기반으로 관리한다.

- 표준코드
- 명칭
- `EXPLICIT / INFERRED`
- 근거 프로젝트
- 사용자 확정 여부

## 8. 사업분야 / 고객유형

인력 전체의 `BIZ` 및 `CUSTOMER_TYPE`은 프로젝트 경력에서 집계하는 것을 원칙으로 한다.

예:

```text
프로젝트 A → 공공 / 공공기관
프로젝트 B → 의료 / 병원
프로젝트 C → 국방 / 군
```

인력 Summary에는 `공공 / 의료 / 국방`, `공공기관 / 병원 / 군`으로 누적 표시한다.

## 9. 프로젝트 경력

프로젝트는 인력 프로필과 검색의 핵심 데이터다.

관리 필드:
- 프로젝트명
- 고객/발주기관
- 고객유형
- 사업분야
- 시작/종료일
- 수행기간
- 직무/역할
- 주요기술
- 전문분야
- 담당업무
- 프로젝트 설명
- 성과/특이사항(선택)
- 원본문서
- 원문 위치
- 정보출처

AI 추출 프로젝트 외에도 관리자가 직접 추가·수정할 수 있다.

프로젝트 중복이 의심될 경우 병합/별도 유지 기능을 제공한다.

## 10. 근무경력

프로젝트와 회사 재직경력은 분리한다.

관리 항목:
- 회사명
- 입사일
- 퇴사일
- 부서
- 직위
- 담당업무
- 재직여부

## 11. 학력

복수 등록 가능:
- 학교
- 전공
- 학위
- 입학년월
- 졸업년월
- 상태

## 12. 자격증/인증

관리 항목:
- 자격명
- 표준명
- 발급기관
- 취득일
- 만료일(있는 경우)
- 증빙문서

자격번호는 검색 핵심정보가 아니므로 MVP 필수항목으로 두지 않는다.

## 13. 프로필 요약

AI가 검색/업무용 요약을 생성하고 관리자가 수정·확정할 수 있다.

- `ai_generated_summary`
- `confirmed_summary`

검색 결과의 핵심 Summary는 DB의 확정된 직무, 등급, 경력, 주요기술, 전문분야, 최근 프로젝트로 구성한다.

## 14. 원문 근거

프로필의 기술, 직무, 전문분야, 프로젝트 등 주요 값에서 근거를 확인할 수 있게 한다.

예:

```text
RAG [근거 3]
  → ○○기관 AI 플랫폼 구축
  → 경력기술서 v3 / p.7
  → [원문 보기]
```

## 15. 정보출처

주요 프로필 값에 출처를 기록한다.

- `SOURCE_AI`: AI 추출 후 사용자 승인
- `SOURCE_USER`: 관리자 직접 입력
- `SOURCE_MIGRATION`: 기존 Excel/자료 이관
- `SOURCE_SYSTEM`: 시스템 계산

최종 Confirmed Profile은 하나로 유지하되 출처와 변경이력을 남긴다.

## 16. 변경이력

프로필 수정 시 다음을 기록한다.
- 작업일시
- 사용자
- 대상 인력
- 변경 항목
- 변경 전/후 값
- 변경사유(선택)

인력 상세의 변경이력 탭에서는 문서 등록, AI 분석 반영, 직접 수정 등을 Timeline으로 보여준다.

## 17. 상태/삭제

인력 상태 예:
- `ACTIVE`
- `INACTIVE`
- `ARCHIVED`
- `DELETED`

삭제는 Soft Delete를 기본으로 하고 관리자만 수행한다.

## 18. 프로필 최신성

최종 문서/프로필 갱신일을 기준으로 최신성을 표시할 수 있다.

- `CURRENT`
- `STALE`
- `UNKNOWN`

MVP에서는 최종 갱신일을 표시하고, 오래된 프로필 경고는 단순 기준으로 제공할 수 있다.
