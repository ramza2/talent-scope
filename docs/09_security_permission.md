# 09. Security & Permission

## 1. 기본 방향

1차 MVP는 사내 직원이 사용하는 시스템을 전제로 권한체계를 단순하게 구성한다.

- `일반사용자`: 조회·검색 중심
- `관리자`: 등록·수정·AI 확정·삭제·코드/사용자 관리

개인정보 마스킹, 세부 필드별 ACL, 부서별 접근권한 등은 고도화 범위로 둔다.

## 2. 인증

MVP에서는 일반적인 ID/Password 로그인 방식을 사용한다.

```text
ID / Password
  → 인증
  → Session 또는 Access Token
  → Backend API 접근
```

기본 원칙:
- 비밀번호 평문 저장 금지
- 안전한 Password Hash 사용
- HTTPS 사용
- 일정시간 미사용 시 세션/Token 만료
- 실제 권한검사는 Backend API에서 수행

SSO/LDAP/AD/2FA 연계는 고도화 범위다.

## 3. 역할

### 일반사용자

가능:
- 인력 목록 조회
- 인력 상세 조회
- 연락처/이메일 등 일반 프로필 정보 조회
- 조건검색
- 자연어검색
- 검색근거 조회
- 일반 이력서/프로필 미리보기
- 일반 문서 다운로드

불가:
- 신규 인력 등록
- 프로필 수정
- AI 분석결과 확정
- 문서 삭제
- 코드관리
- 사용자관리

### 관리자

일반사용자 권한 전체 + 다음 기능:
- 신규 인력 등록
- 문서 업로드
- AI 분석/재분석
- AI 분석결과 검토·확정
- 프로필/프로젝트 수정
- 문서 삭제/복원
- 코드관리
- 사용자관리
- AI 분석현황 및 주요 이력 확인

## 5. 개인정보 정책

사내 일반사용자는 업무상 필요한 인력 프로필의 일반 개인정보를 마스킹 없이 조회할 수 있다.

조회 대상 예:
- 이름
- 연락처
- 이메일
- 거주지역
- 소속
- 직무/등급/경력
- 기술/전문분야
- 프로젝트
- 학력/자격
- 일반 이력서/프로필 원문

MVP에서는 개인정보 마스킹이나 필드별 조회권한을 제공하지 않는다.

## 6. 구조화/임베딩 제외 정보

다음 정보는 검색·추천 목적에 불필요하므로 Profile JSON 및 임베딩 대상에서 제외한다.

- 주민등록번호
- 신분증번호
- 계좌번호
- 가족관계
- 기타 불필요한 민감정보

상세주소도 가능하면 시/도 등 업무상 필요한 지역 수준만 구조화한다.

## 7. 민감문서

신분증, 통장사본, 주민등록 관련 문서 등은 1차 MVP 문서 관리대상에서 제외한다.

향후 필요 시 별도 문서분류 및 접근권한 정책으로 고도화한다.

## 8. AI 처리 개인정보 원칙

AI Prompt에는 주민등록번호, 계좌번호, 신분증번호 등의 민감정보를 출력하지 않도록 명시한다.

Profile/Project 임베딩에는 연락처, 이메일, 상세주소, 생년정보 등 검색에 불필요한 개인정보를 포함하지 않는다.

원본문서 Chunk 임베딩 구현 시 개인정보 포함 가능성을 고려하여 사내 한정 Search Index로 운영하고, 필요하면 고도화 단계에서 PII 제거/마스킹 파이프라인을 추가한다.

## 9. 변경이력

최소 기록 대상:
- 인력 생성
- 프로필 수정
- 인력 삭제/복원
- 문서 업로드
- 문서 삭제/복원
- AI 분석결과 확정
- 사용자 생성/수정/비활성

기록 항목:
- 사용자
- 작업일시
- 대상
- 작업유형
- 변경 전/후 값(적용 가능한 경우)

## 10. 문서 다운로드 이력

원본 이력서는 개인정보를 포함하므로 다운로드 이력을 기록한다.

예:

```text
2026-09-04 15:02
사용자: 김○○
인력: 홍길동
문서: 홍길동_경력기술서_v3.pdf
Action: DOWNLOAD
```

## 11. Soft Delete

인력과 문서는 기본적으로 논리삭제한다. 관리자만 삭제/복원할 수 있다. 물리삭제 주기/보존정책은 운영단계에서 별도 정의한다.

## 12. AI Runtime 보호

Frontend에서 ALZI LLM/VLM Runtime을 직접 호출하지 않는다.

```text
Frontend
  → TalentScope Backend
    → LLM / VLM Runtime
```

Runtime Endpoint, 인증정보, Prompt 구성 등은 Backend에서 관리한다.

## 13. 고도화 범위

- 개인정보 마스킹 설정
- 필드별 ACL
- 부서/프로젝트별 권한
- 문서별 접근권한
- 개인정보 조회사유 입력
- 다운로드 승인 Workflow
- IP 접근제어
- SSO/LDAP/AD
- 2FA
